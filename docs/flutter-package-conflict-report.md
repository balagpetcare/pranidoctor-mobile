# Flutter package dependency audit — `open_file` → `open_filex`

**Project:** Prani Doctor (`pranidoctor_mobile`)  
**Date:** 2026-05-12  
**Flutter SDK (verified):** 3.41.9 (stable), Dart 3.11.5  

## Executive summary

The deprecated [`open_file`](https://pub.dev/packages/open_file) **3.5.0** stack (including federated implementations such as **`open_file_mac`** on Apple platforms and **`open_file_linux`** on Linux) was removed from the dependency graph. The app now depends on [`open_filex`](https://pub.dev/packages/open_filex) **^4.7.0** (resolved **4.7.0**), a maintained fork that avoids the broken macOS federated plugin path and aligns with current Flutter tooling.

`flutter pub get` completes successfully; `flutter analyze` reports no errors (existing **info**-level lints elsewhere in the repo are unchanged).

## 6. Stale plugin cache and local hygiene

After changing plugins, if a machine or CI job still sees old native registrations:

1. Run **`flutter pub get`** from the project root (already verified).
2. If native build caches persist: **`flutter clean`**, then `flutter pub get`.
3. **iOS:** from `ios/`, `pod install` (or delete `Pods` + `Podfile.lock` only if you have a reproducible pod resolution strategy).
4. **macOS:** same idea under `macos/` if CocoaPods is used there.

Ephemeral symlink trees under `**/flutter/ephemeral/.plugin_symlinks` are tooling-managed and refresh on Pub/Flutter commands.

## 9. Enterprise stability recommendations

- Keep **`pubspec.lock`** committed for reproducible CI and release builds.
